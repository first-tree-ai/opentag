# 电脑连接管理

Account → Computer 管理连接。Agent 设置展示所用电脑，并链接到这里。账户只有一台电脑时直接展示；已有多台
电脑的账户保留明确选择。不在此页加入 Agent 列表或 runtime 配置。

## 状态与交互

电脑身份、状态行、说明、主按钮位置和更多菜单使用固定布局。

| 已确认的状态 | 说明 | 主操作 |
| --- | --- | --- |
| 在线 | Agent 可以使用这台电脑。 | 无 |
| 离线 | 请开机或唤醒这台电脑，并检查网络连接。 | 查看连接帮助 |
| 已断开 | 重新连接后，Agent 即可使用这台电脑。 | 重新连接 |
| 无法读取 | 无法获取这台电脑的状态。 | 重试 |

“状态暂不可用”表示缺少可靠信息，不是另一种持久连接状态。准备指令、等待兑换、检查状态属于操作进度，
不会替换连接状态标记。

- 帮助复用 onboarding 的指令块：一个复制操作，可展开完整内容。复制的始终是完整指令。
  “助手要求修复连接？”展开后才显示更换连接凭据的入口。
- 重新连接使用针对原电脑的修复码。关闭弹窗后保留指令并继续检查连接；“查看指令”重新打开同一条指令，
  不会再次生成。卡片展示过期状态，只有用户主动操作才生成新指令。复制不代表连接成功。
- 确认在线后更新卡片和已打开的弹窗。关闭后焦点回到原操作；该操作消失时回到卡片。
- 更多菜单保留断开连接与已有的删除操作。断开确认默认聚焦“保持连接”，请求期间不可关闭。
  丢失响应时先检查状态，再允许新的变更操作。
- 删除保留输入电脑名确认的机制；仍有关联的未删除 Agent 时拒绝删除。

## 权限与兼容性

断开通过账户授权的 `POST /api/v1/computers/:computerId/disconnect` 完成，沿用会话和 CSRF 校验。
它撤销有效凭据和未兑换的修复码，并清除在线信息；保留电脑身份、Agent 关联、配置和本地文件。
此接口不能断开云电脑。

事务写入 `computers.disconnected_at`，针对原电脑的修复成功后清除。重置 onboarding 时也清除此保留标记，
避免旧电脑重新出现在列表。已删除的电脑继续隐藏。

携带 `x-opentag-computer-access: 1` 的列表请求包含主动断开的电脑和 `disconnected` 状态；旧客户端仍只获取
有效凭据对应的电脑，保持 online/offline 协议。传输层在线状态和 provider-readiness 协议不变。

连接码签发、兑换、重置、删除、断开均先锁定所属 Account。兑换先无锁读取不可变的签发账户，再锁定账户，
随后重新读取并校验已锁定的连接码。这样旧修复码的并发兑换不能恢复已撤销的权限，即使之后又完成了新的连接。
事务提交后关闭连接；身份验证和 runtime 凭据检查独立保障撤销生效。
