# Cloud billing

Cloud model calls and connectivity probes go through `llm-router`, which uses self-hosted LiteLLM internally. The router owns provider usage normalization, durable request status, and reconciliation. OpenTag owns trusted Account/Agent attribution, bounded forwarding, and usage reporting. The private `@opentag/cloud-billing` package runs inside OpenTag and owns customer prices, credits, and Stripe Checkout. The application and billing package share PostgreSQL; the public repository owns the `billing` schema and migrations. Local Agents use their existing execution and usage paths.

## Usage and prices

Before dispatch, OpenTag creates one durable call with its Account, Agent, optional Session, source, gateway, model, and customer rate snapshot. The call UUID is the router `Idempotency-Key`. Execution attribution comes from verified grants and database relationships; connectivity probes use the ownership-checked Agent and authenticated Account. The ledger contains no prompts or response content.

OpenTag forwards completions without parsing token usage. After completion or interruption it reads `GET /v1/requests/usage?idempotency_key=<call UUID>` with the same server-only router tenant credential used for completions. The router returns the correlated request ID, model, and one status: `complete` with all four token counters, `no_charge`, or `pending`. A typed `request_not_found` 404 is unknown usage, not evidence of a free call. OpenTag validates the identity, model, and counters before settling.

Canonical input totals include ordinary input, cached reads, and cache writes. Cached read and write counts are disjoint subsets of input. Output includes reasoning tokens. The router normalizes these counts and handles provider-specific responses once. Available models need verified input/output limits and, when customer billing is enabled, customer prices.

Customer prices live in `src/prices.json` in the private billing repository, keyed by gateway and exact router model IDs. The default gateway ID is `llm-router`. Each model has `input`, `cachedInput`, `cacheWrite`, and `output` rates expressed as decimal USD strings per million tokens, with up to six decimal places. The package validates the file at startup and converts rates to integer microdollars exactly. Settlement calculates `(input-cached-write)*input_rate + cached*cached_rate + write*write_rate + output*output_rate`, divides by one million, and rounds up once using integer arithmetic. Saved rates make price changes apply only to future calls. Customer prices are independent of the router's provider-cost ledger. To update prices, commit the private price book, update the application's `cloud-billing.json` pin, and deploy the application. The price book stays out of public source and is bundled in the production image.

Account and Agent cloud totals read the same finalized call measurements, including calls made with customer billing disabled. Local report tokens and cloud ledger tokens are combined using the execution origin captured at dispatch; cloud task-report tokens do not enter aggregates. Task counts and outcomes remain task-report metrics. Account usage includes connectivity probes and offers 1, 7, 30, and 90-day totals and daily charts. Missing counts are partial data.

## Credits and settlement

Enable `OPENTAG_CLOUD_BILLING_ENABLED=true` in the cloud image. Admission locks the Account in a short transaction, applies payment blocks, checks available credit, unresolved calls, and concurrency, then inserts the priced call before dispatch. Balance is granted credit minus finalized debits. The default starting grant is $1 once per Account, with two concurrent calls per Account. Billing-disabled cloud calls use the same router status and reporting path with no debit.

Settlement locks the Account and call, then saves all final counts and the credit debit together in one transaction. Repeated settlement cannot debit twice or change finalized counts. Already admitted calls may exceed remaining credit; the debit is capped at the available balance and OpenTag absorbs the difference. The execution grant bounds output to at most 8,192 tokens. Body, response, timeout, and concurrency limits constrain exposure; timeout alone does not guarantee a dollar ceiling. Verify exposure for offered models before accepting real payments.

Requests cancelled before dispatch, router-confirmed pre-dispatch rejections (`X-Router-Dispatch: not_dispatched`), and router `no_charge` results finalize without a debit. OpenTag uses a fresh key and sends each model request once. It never redispatches uncertain executions. Unknown or pending usage becomes `pending_usage` and blocks new billed calls for that Account; top-ups and balance reads remain available. The public worker retries only status reads, with persisted delays from 30 seconds to one hour. Interrupted provider execution and missing usage are reconciled in the router; OpenTag reads the resulting final status.

Startup marks abandoned calls pending before cloud readiness, including billing-disabled calls. Stale in-flight records become pending after the request timeout plus a grace period. Resolve pending calls and drain active calls before changing the gateway identity or endpoint. Operators can write off reviewed unresolved customer calls with `node scripts/write-off.mjs <call-id> <reason>` from the built private checkout using the application environment; the reason is recorded.

## Payments

Account displays one available USD balance, including starting and purchased credit, with custom top-ups from $10 to $1,000 in cents. Stripe-hosted Checkout returns to `/account`; only verified paid Stripe sessions add credit. The signed webhook endpoint is `/stripe/webhook`. Register `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `charge.refunded`, and `charge.dispute.created`. Refunds remove purchased credit once; refunds and disputes block cloud spending for operator review. Events received before fulfillment remain durable. Provider availability does not affect payment fulfillment or balance reads.

Configure `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, and optionally `BILLING_FREE_CENTS` and `BILLING_MAX_CONCURRENT_PER_ACCOUNT` in the private package's application environment. Prices come from the bundled private price book. Use Stripe test mode for acceptance testing. Auto-recharge, subscriptions, request reservations, and a billing administration UI are outside this MVP.

## CapRover deployment

The public `Docker`, `Deploy Staging`, and `Deploy Runner` workflows ship the application and billing package together. `cloud-billing.json` pins the exact private package commit. Configure `OPENTAG_BILLING_READ_TOKEN` with read-only Contents access to `first-tree-ai/opentag-billing`; trusted main image builds check out that revision, run its checks and tests against the application, and bundle it into `ghcr.io/first-tree-ai/opentag:<application SHA>`. The image records both source revisions. Pull-request and default local images build without private access. The production image contains the private code and may be public; runtime secrets stay in CapRover.

Deploy the router usage endpoint first and verify it using the OpenTag tenant key (`llm` scope). Set `OPENTAG_CLOUD_MODEL_UPSTREAM_BASE_URL` to its `/v1` base and `OPENTAG_CLOUD_MODEL_MASTER_KEY` to that tenant key. Check complete, pending, missing, and rejected-call status behavior against every offered model. Then enable cloud identities, cloud models, billing, and `OPENTAG_AUTO_MIGRATE=true`. Startup applies the public migrations before constructing the services. The staging flow publishes the application and CLI/Runner, deploys the application, then activates the matching Runner. `/cloud-readyz` verifies application and billing revisions; `/readyz` remains independent of billing availability.

Use one application replica, no predeploy function, and stop-first updates and rollbacks. Set `UpdateConfig` to `{"Order":"stop-first","Parallelism":1,"FailureAction":"pause"}`, `RollbackConfig` to `{"Order":"stop-first","Parallelism":1}`, and `TaskTemplate.ContainerSpec.StopGracePeriod` to at least `(OPENTAG_CLOUD_MODEL_REQUEST_TIMEOUT_MS + 30000) * 1000000` nanoseconds. The default 600-second timeout requires `630000000000`. This ensures startup recovery cannot mistake another live process's calls for abandoned work. Let the image supply `OPENTAG_BUILD_REVISION` and `OPENTAG_BILLING_REVISION`. Back up the shared database. Applied migrations require compatible application images; prefer forward fixes.

## Acceptance testing

Use a disposable router PostgreSQL/Redis pair, the OpenTag test database, and Stripe test mode. Verify a normal completion and a streamed completion record exactly the router counts (including cache reads/writes), with one corresponding credit debit. Replay settlement and confirm counts and balance are unchanged. Interrupt a stream, inspect pending status, reconcile in the router, and confirm the OpenTag worker settles the same call without another model execution. Confirm rejected requests do not debit, tenant keys cannot read each other's usage, malformed or unknown usage remains pending, and billing-disabled cloud calls still appear in usage. Finally complete a test Checkout and replay its signed webhook to verify a single credit grant.
