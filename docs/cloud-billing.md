# Cloud billing

Cloud model calls and connectivity probes go through `llm-router`, which uses self-hosted LiteLLM internally. The router owns provider usage normalization, durable request status, and reconciliation. OpenTag owns trusted Account/Agent attribution, bounded forwarding, and usage reporting. The private `@opentag/cloud-billing` package runs inside OpenTag and owns customer prices, credits, and Stripe Checkout. The application and billing package share PostgreSQL; the public repository owns the `billing` schema and migrations. Local Agents use their existing execution and usage paths.

## Usage and prices

Before dispatch, OpenTag creates one durable call with its Account, Agent, optional Session, source, gateway, model, and customer rate snapshot. The call UUID is the router `Idempotency-Key`. Execution attribution comes from verified grants and database relationships; connectivity probes use the ownership-checked Agent and authenticated Account. The ledger contains no prompts or response content.

OpenTag forwards completions without parsing token usage. After completion or interruption it reads `GET /v1/requests/usage?idempotency_key=<call UUID>` with the same server-only router tenant credential used for completions. The router returns the correlated request ID, model, and one status: `complete` with all four token counters, `no_charge`, or `pending`. A typed `request_not_found` 404 is unknown usage, not evidence of a free call. OpenTag validates the identity, model, and counters before settling.

Canonical input totals include ordinary input, cached reads, and cache writes. Cached read and write counts are disjoint subsets of input. Output includes reasoning tokens. The router normalizes these counts and handles provider-specific responses once. Available models need verified input/output limits; model availability and permissions are managed by the gateway.

Customer rates live in `src/plans.json` in the private billing repository, keyed by plan ID. Each plan has `input`, `cachedInput`, and `output` rates expressed as decimal USD strings per million tokens, with up to six decimal places. Cached reads are discounted; cache writes cost ordinary input. Every billing Account has a `plan_id`, defaulting to `standard`. Rates apply regardless of gateway or model; the call still records both for attribution. Operators can add rate cards and assign them with `node --env-file=/path/to/opentag/.env scripts/set-plan.mjs <account-id> <plan-id>` from the built private checkout. Assignments use the Account lock and preserve credit. Plans do not add subscriptions, a customer selector, or model access rules.

The package validates every plan at startup, requires `standard`, and converts rates to integer microdollars exactly. Unknown assigned plans reject new calls. Settlement calculates `(input-cached)*input_rate + cached*cached_rate + output*output_rate`, divides by one million, and rounds up once using integer arithmetic. Each call saves its account's rates at admission, so plan and price changes apply only to future calls. Customer rates are independent of the router's provider-cost ledger; review the rates alongside the offered models to avoid selling expensive models below cost. To update rates, commit the private plan file, update the application's `cloud-billing.json` pin, and deploy the application. The plan file stays out of public source and is bundled in the production image.

Account and Agent cloud totals read the same finalized call measurements, including calls made with customer billing disabled. Local report tokens and cloud ledger tokens are combined using the execution origin captured at dispatch; cloud task-report tokens do not enter aggregates. Task counts and outcomes remain task-report metrics. The call ledger does not establish per-task coverage, so cloud tasks are conservatively excluded from measured task counts. Account usage includes connectivity probes and offers 1, 7, 30, and 90-day totals and daily charts. Missing counts are partial data.

## Credits and settlement

Enable `OPENTAG_CLOUD_BILLING_ENABLED=true` in the cloud image. Admission locks the Account in a short transaction, selects its plan rates, applies payment blocks, checks available credit, unresolved calls, and concurrency, then inserts the priced call before dispatch. Balance is granted credit minus finalized debits. The default starting grant is $1 once per Account, with two concurrent calls per Account. Billing-disabled cloud calls use the same router status and reporting path with no debit.

Settlement locks the Account and call, then saves all final counts and the credit debit together in one transaction. Repeated settlement cannot debit twice or change finalized counts. Already admitted calls may exceed remaining credit; the debit is capped at the available balance and OpenTag absorbs the difference. The execution grant bounds output to at most 8,192 tokens. Body, response, timeout, and concurrency limits constrain exposure; timeout alone does not guarantee a dollar ceiling. Verify exposure for offered models before accepting real payments.

Requests cancelled before dispatch, router-confirmed pre-dispatch rejections (`X-Router-Dispatch: not_dispatched`), and router `no_charge` results finalize without a debit. OpenTag uses a fresh key and sends each model request once. It never redispatches uncertain executions. Unknown or pending usage becomes `pending_usage` and occupies one of the Account’s billed-call slots alongside active calls (two slots by default). Remaining slots stay available; when pending usage fills the capacity, the Account page shows a temporary pause. Top-ups and balance reads remain available. The public worker retries only status reads every five seconds for the first 150 seconds after a call ends, covering the router’s default 120-second disconnect drain, then backs off from 30 seconds to one hour. Unresolved calls emit one structured `cloud_usage_unresolved` operator error with call ID, Account ID, and pending age when fast retries end. Interrupted provider execution and missing usage are reconciled in the router; OpenTag reads the resulting final status.

Startup marks abandoned calls pending before cloud readiness, including billing-disabled calls. Stale in-flight records become pending after the request timeout plus a grace period. Resolve pending calls and drain active calls before changing the gateway identity or endpoint. Operators can write off reviewed unresolved customer calls with `node scripts/write-off.mjs <call-id> <reason>` from the built private checkout using the application environment; the reason is recorded.

## Payments

Account displays one available USD balance, including starting and purchased credit, with custom top-ups from $10 to $1,000 in cents. Stripe-hosted Checkout returns to `/account`; only verified paid Stripe sessions add credit. The signed webhook endpoint is `/stripe/webhook`. Register `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `charge.refunded`, and `charge.dispute.created`. Refunds remove purchased credit once; refunds and disputes block cloud spending for operator review. Events received before fulfillment remain durable. Provider availability does not affect payment fulfillment or balance reads.

Configure `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, and optionally `BILLING_FREE_CENTS` and `BILLING_MAX_CONCURRENT_PER_ACCOUNT` in the private package's application environment. Rates come from the bundled private plan file. Use Stripe test mode for acceptance testing. Auto-recharge, subscriptions, request reservations, and a billing administration UI are outside this MVP.

## CapRover deployment

`OPENTAG_CLOUD_BILLING_ENABLED` defaults to `false` and is independent per application environment. Keep it unset or `false` in production and set it to `true` in staging to test billing. Bundling the private package does not activate billing. When disabled, the server does not load the private package, initialize Stripe, enforce credit checks, grant starting credit, or register the payment webhook. The credits section stays hidden until billing is confirmed enabled, including during loading or a failed initial settings read. Cloud token usage continues to be recorded without charges. Deployment checks require billing readiness and billing-specific rollout settings only when the target application has billing enabled.

The public `Docker`, `Deploy Staging`, and `Deploy Runner` workflows ship the application and billing package together. `cloud-billing.json` pins the exact private package commit. Configure `OPENTAG_BILLING_READ_TOKEN` with read-only Contents access to `first-tree-ai/opentag-billing`; trusted main image builds check out that revision, run its checks and tests against the application, and bundle it into `ghcr.io/first-tree-ai/opentag:<application SHA>`. The image records both source revisions. Pull-request and default local images build without private access. The production image contains the private code and may be public; runtime secrets stay in CapRover.

Deploy the router usage endpoint first and verify it using the OpenTag tenant key (`llm` scope). Set `OPENTAG_CLOUD_MODEL_UPSTREAM_BASE_URL` to its `/v1` base and `OPENTAG_CLOUD_MODEL_MASTER_KEY` to that tenant key. Check complete, pending, missing, and rejected-call status behavior against every offered model. Then enable cloud identities, cloud models, billing, and `OPENTAG_AUTO_MIGRATE=true`. Startup applies the public migrations before constructing the services. The staging flow publishes the application and CLI/Runner, checks CapRover billing safety before deploying the application, then activates the matching Runner. Billing-enabled deployment requires both `/readyz` application readiness and `/cloud-readyz` billing readiness at the expected image revision.

Use one application replica, no predeploy function, and stop-first updates and rollbacks. Set `UpdateConfig` to `{"Order":"stop-first","Parallelism":1,"FailureAction":"pause"}`, `RollbackConfig` to `{"Order":"stop-first","Parallelism":1}`, and `TaskTemplate.ContainerSpec.StopGracePeriod` to at least `(OPENTAG_CLOUD_MODEL_REQUEST_TIMEOUT_MS + 30000) * 1000000` nanoseconds. The default 600-second timeout requires `630000000000`. This ensures startup recovery cannot mistake another live process's calls for abandoned work. Let the image supply `OPENTAG_BUILD_REVISION` and `OPENTAG_BILLING_REVISION`. Back up the shared database. Applied migrations require compatible application images; prefer forward fixes.

## Acceptance testing

Use a disposable router PostgreSQL/Redis pair, the OpenTag test database, and Stripe test mode. Verify a normal completion and a streamed completion record exactly the router counts (including cache reads/writes), with one corresponding credit debit. Replay settlement and confirm counts and balance are unchanged. Interrupt a stream, inspect pending status, and confirm the OpenTag worker settles the same call within the next recovery tick after the router finalizes, without another model execution. Leave one call unresolved and confirm another call can proceed; fill both slots with unresolved calls and confirm new requests pause until settlement or an operator write-off. Confirm rejected requests do not debit, tenant keys cannot read each other's usage, malformed or unknown usage remains pending, and billing-disabled cloud calls still appear in usage. Assign a second test plan while a call is outstanding: the outstanding call must keep its original rates, new calls must use the assigned plan, and another Account must keep its default. Confirm different models use the same plan rates and unknown plans reject new calls without blocking settlement. Finally complete a test Checkout and replay its signed webhook to verify a single credit grant.
