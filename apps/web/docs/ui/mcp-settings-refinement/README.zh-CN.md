# MCP 设置优化

这些截图展示与 `main` 的 MCP 管理流程合并后的当前 React 组件。截图使用本地预览中的一次性示例数据，并非已登录的服务账号。

- [桌面设置（1440 × 900）](settings-desktop.jpg)
- [桌面认证（1440 × 900）](authentication-desktop.jpg)
- [设置（320 × 640）](settings-320.jpg)
- [需要认证（320 × 640）](disconnected-320.jpg)

设置页保留 Server address 标签，去掉重复的 Agent 范围说明和 Server information 展开项，导航行统一为 44 px，并采用克制的悬停背景。Back 返回父弹窗；Close 和 Escape 关闭整个流程。从子弹窗返回后保留草稿、展开状态和滚动位置。认证前仍要求先保存修改过的连接设置。

认证页为不同方式的内容预留空间，切换浏览器登录、令牌和无需认证时，弹窗位置及底部操作区保持不变。设置和认证使用相同顶部锚点，可用空间不足时仅内容区滚动。工具弹窗根据初始列表大小确定高度，设有最小列表区域，以视口剩余高度为上限，搜索时保持高度。

浏览器布局检查覆盖 320、390、768、1440 px 宽度、较矮视口、已连接及需要认证状态、请求头模式切换、三种认证方式、工具搜索及空结果。在 320 px 下，展开设置在内部滚动，底部操作区保持可见。当前 1440 px 认证弹窗的三种方式测得相同顶部位置和高度；工具搜索无结果时尺寸也保持不变。

合并前还进行了独立的本地端到端验证，使用真实应用、Fastify、PostgreSQL 和受控 MCP/OAuth 服务，覆盖保存与取消、请求头模式、令牌认证、浏览器 OAuth、草稿重基、工具刷新与搜索、长列表及移除操作。该服务使用客户端 ID 元数据文档。未验证真实 Notion/Linear 认证和动态客户端注册（DCR）。独立审查发现的既有 DCR 注册绑定问题不在本次修改范围内。
